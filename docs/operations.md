# Эксплуатация и границы первой версии

Runtime: один polling process. SQLite WAL, FK, busy_timeout 5s. httpx timeout 40s,
connect 10s; polling Telegram 25s. На send нет автоматических retries. Управляющий
Telegram-бот используется для входящих медиа и ответов; подключённые боты —
для отправки в собственные назначения. Бизнес-подключение использует центральный токен.

Окно жизни черновика и его delivery history — 24 часа, очищается при следующем
черновике. update_id хранится до 7 суток, очищается при следующем update.
Долговременный audit trail/архив публикаций пока не предоставляются.
account delete каскадно удаляет targets и их deliveries; drafts автоматически
истекают, отключение аккаунта не отзывает выданный платформой токен — отзовите
его также на площадке. Fernet key rotation пока вручную с переподключением аккаунтов.

Входящие update_id записываются до исполнения: при аварии команда может
остаться необработанной. Повтор действия — новая команда/новый черновик после
проверки /status и фактической площадки. Гарантия at-most-once attempts,
не exactly-once effects. В частности, падение после удалённой публикации до
записи ID не позволяет автоматически выяснить результат Telegram/MAX.

SQLite и однопроцессная очередь последовательны; длительный медиа-upload
может задержать обработку следующего пользователя. Capacity/SLA не измерены.
Пересмотр: отдельный durable worker + PostgreSQL после определения нагрузки,
лимитов и требований к восстановлению. Не увеличивать число реплик с этой БД.

Для backup остановите процесс, создайте SQLite backup и сохраните ключ в
секрет-хранилище отдельно. Восстановление проверять на отдельной БД; не
подключать восстановленный staging к production бот-токену. Логи не содержат
payload/URL/токенов. Для пилота включите allowlist пользователей.

## Незавершённые продуктовые направления

- Личные Telegram MTProto-сессии: требуется согласовать режим авторизации,
  зарегистрировать Telegram API application, реализовать login/2FA/QR,
  encrypted sessions, logout/revocation и политику использования.
- MAX: подтверждён только официальный Bot API; личный user login и истории
  не выдаются за доступные методы.
- ВК: OAuth-app onboarding вместо передачи user access token, разрешения
  scopes, approval приложения, refresh/revocation; VK Клипы — отдельная
  подтверждённая интеграция, обычный video upload её не заменяет.
- Альбомы, расписание, постоянная история отправок и групповое подтверждение.

Эти пункты не считаются реализованными; текущий код — первая версия
для официальных токенов ботов, Telegram Business и VK user token.

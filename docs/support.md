# Техподдержка RelayPost

Реализовано в feature/support; production 0.1.0 этого кода не содержит.
Сценарий повторяет planerBot: личное обращение владельцу, ответ через бота.

## Пользователь

1. `/support` или ссылка `https://t.me/relay_PostBot?start=support`.
2. Ответить на приглашение текстом до 3000 UTF-16 единиц. Бот предупреждает,
   что текст, имя и Telegram ID получит поддержка. Не отправлять токены и пароли.
3. Также можно сразу `/support текст`.
4. Бот сообщает номер и факт подтверждённой доставки либо честно сообщает отказ
   или неопределённый результат. Не более одного нового обращения в минуту.
5. `/cancel`, `/start`, `/help` отменяют приглашение. Приглашение действует сутки.

Обычный текст не становится обращением: нужен `/support` либо reply на последнее
сохранённое приглашение своего бота. Сообщения в группах бот не собирает.
Фото, видео и файлы поддержки пока не принимаются. Ответ на сообщение с ответом
поддержки не создаёт обращение; для продолжения используется `/support`.

## Владелец

SUPPORT_CHAT_ID — положительный числовой ID личного Telegram-аккаунта, 0 выключает
приём. Получатель должен запустить RelayPost и не блокировать его. Хранить ID в
приватном окружении и GitHub Secret SUPPORT_CHAT_ID; не в публичном репозитории.
Не переносить локальную настройку plannerBot вслепую: там сейчас 0.

Владелец получает карточку обращения и отвечает на неё текстом. Бот находит
пользователя по сохранённому message_id и получателю, проверяет текущего владельца,
отправителя исходной карточки и отсутствие forward_origin. Номера в тексте
карточки не определяют адресата. Ответ пользователю — новое сообщение от имени
RelayPost, без forward, ника и ID сотрудника. При закрытом пилоте владелец может
отвечать в поддержку, но это не даёт ему права публиковать вне allowlist.

## Данные и доставка

SQLite v1 → v2: только новые support_prompts и support_messages, без изменения
старых строк/таблиц. Транзакционная миграция применяется до polling; backfill N/A.
Вызовы сети выполняются после commit. Обращения и ответы имеют уникальный
(owner,source_id), отправки захватываются в состоянии sending до сетевого вызова.
BEGIN IMMEDIATE сериализует проверку повтора и минутного лимита. Индекс
support_owner_created обслуживает ограниченный запрос лимита, уникальный
(recipient,remote_id) — поиск карточки. Запросы параметризованы.

Подтверждение Telegram → sent; отказ, включая 429 → failed; таймаут/5xx/неполный
ответ → unknown. После перезапуска незавершённые sending становятся unknown.
Автоматических повторов нет, в том числе после 429; это отличие от очереди
plannerBot. Не обещаем exactly-once: сбой после Telegram и до commit оставляет
unknown. Сверка — по номеру и закрытой БД, никаких секретных payload в логах.
Сообщения отправляются plain text с отключёнными link previews через тот же
Telegram-only proxy. История поддержки не удаляется вместе с черновиками.
Retention и пользовательский просмотр истории поддержки — следующие задачи.

## Выпуск и восстановление

PR → develop → main → новый semver tag. Pipeline передаёт SUPPORT_CHAT_ID,
проверяя формат до записи private env. Без секрета используется 0. Сначала
настроить проверенного получателя; не отправлять пробные реальные обращения
без явного разрешения. Живой round trip пользователь/поддержка пока не проверен.

Перед v2 deployment штатный скрипт останавливает старый poller и делает SQLite
backup. Старый код 0.1.0 отвергает schema v2: автоматический возврат старого
контейнера после уже выполненной миграции не восстановит сервис. При ошибке
после миграции использовать forward fix либо остановить poller и восстановить
отдельно проверенную копию БД/старый env по инструкции оператора; не делать down
migration и не удалять обращения. Восстановление production в тестах не выполнялось.

Проверены пустая/заполненная v1, сохранность черновиков, повторный startup,
integrity_check/foreign_key_check, replay, лимит, приватность адресата, поддельные
reply/forward, Unicode, закрытый пилот, timeout/5xx/429, crash recovery и env injection.
Сеть тестов — MockTransport, БД настоящая SQLite.
Контракты: [sendMessage и ForceReply](https://core.telegram.org/bots/api), проверены 2026-10-20.

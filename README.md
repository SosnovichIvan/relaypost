# RelayPost

Telegram-бот для публикаций из одного диалога в несколько аккаунтов Telegram,
MAX и ВК. Подключения, права и тип контента определяют доступные кнопки отправки.

## Возможности

- Несколько подключений каждой платформы, разделённых по Telegram-пользователю.
- Проверка токена и прав назначения при добавлении и перед каждой отправкой.
- Поиск до 20 площадок MAX и до 20 сообществ ВК плюс личной стены: `/discover ID`.
- Черновик из текста, фотографии или видео; отдельное подтверждение каждой отправки.
- Истории Telegram через бизнес-подключение; истории ВК через разрешённый API.
- Зашифрованное хранение токенов, удаление команды с токеном перед проверкой.
- Журнал доставки, защита от повторной отправки кнопкой, сохранение неизвестного
  исхода при таймауте/перезапуске. Автоматических повторов публикаций нет.

| Подключение | Текст | Фото/видео | История | Назначения |
| --- | --- | --- | --- | --- |
| Telegram Bot API | Да | Да | — | Каналы, группы с правами администратора |
| Telegram Business | — | — | Да | Подключённый бизнес-аккаунт с `can_manage_stories` |
| MAX Bot API | Да | Да | Нет в используемом API | Чаты и каналы, где бот администратор |
| ВК user access token | Да | Да | При доступе приложения/аккаунта | Личная стена, управляемые сообщества |

Вход в личные Telegram-аккаунты по QR/коду (MTProto), личные MAX-сессии,
VK OAuth login и публикация именно VK Клипов пока не реализованы. Обычные
видеопубликации поддержаны. Токен ВК должен принадлежать пользователю и давать
права API для нужных методов; не всякое приложение получает эти разрешения.
Не обещаем формат, который площадка не разрешила. Истории MAX не предлагаются.

## Локальный запуск

Python 3.9+; CI и Docker используют Python 3.12. Необходимы BotFather token
управляющего Telegram-бота и постоянный ключ шифрования.

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.lock
cp .env.example .env
.venv/bin/python -c 'from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())'
```

Заполните `.env`: `TELEGRAM_BOT_TOKEN`, `RELAYPOST_ENCRYPTION_KEY`.
Не передавайте реальные токены в issues, PR и логи. Для закрытого пилота задайте
`RELAYPOST_ALLOWED_USERS=123456789,987654321`; пустой список открывает доступ всем.

```sh
set -a
source .env
set +a
make run
```

Запускайте **одну** реплику на токен/SQLite. Polling отключает webhook этого
управляющего бота, сохраняя ожидающие updates. Для Telegram Business включите
business mode в BotFather, затем подключите бота в настройках бизнес-аккаунта
и выдайте право управления историями. Фактическая доступность зависит от Telegram.

## Использование

1. Откройте бота и отправьте `/start`.
2. В личном диалоге: `/connect telegram ТОКЕН_ОТДЕЛЬНОГО_БОТА`,
   `/connect max ТОКЕН_БОТА` или `/connect vk USER_ACCESS_TOKEN`.
   Команда удаляется **до** использования токена; если удалить её не удалось,
   подключение отклоняется. Telegram всё равно получает исходное сообщение:
   используйте отдельные отзываемые токены. Пароли/OTP бот не запрашивает.
3. `/accounts` покажет номера подключений. `/discover 1` найдёт MAX/ВК-площадки.
   Telegram: `/add 1 @channel` или `/add 1 -1001234567890`.
   ВК: положительный ID собственной стены или отрицательный ID сообщества.
4. Для историй ВК: `/addstory 2 -12345` (только после проверки разрешения API).
   Истории Telegram появляются автоматически при business connection update.
5. Отправьте одно фото, видео или текст. Кнопки показывают доступные
   назначения и форматы. Нажатие публикует контент в выбранном месте.
6. `/status` покажет `sent`, `failed`, `unknown`, `sending` и ID результата.
   После `unknown` сначала проверьте площадку вручную; новый черновик может
   создать дубль. `/disconnect ID` удаляет подключение и его назначения.

Медиа ограничены 20 МБ из-за пути скачивания через Telegram Bot API. Альбомы,
расписание и массовая отправка одной кнопкой пока отсутствуют. Для историй
соблюдайте требования площадки к размеру/длительности; текст истории ВК должен
быть нанесён на изображение/видео, отдельная подпись не принимается этим API.
MAX может отклонить ещё обрабатываемое вложение — бот сообщит об этом.
ВК video upload может создать видео до отправки поста; отказ поста не откатывает
загрузку видео. Сетевые операции площадок не являются одной транзакцией.

## Docker

```sh
docker compose up --build -d
```

SQLite хранится в volume `/data`, ключ — в `.env`. Не теряйте ключ: без него
сохранённые токены не расшифровать. Резервируйте БД и ключ отдельно.
Перед production проверьте восстановление, отзыв токенов, реальные права,
сертификаты MAX и публикацию в выделенных тестовых каналах. TLS не отключается.
Сборка контейнера и запуск non-root с миграцией SQLite проверены локально;
живая доставка в этой проверке не выполнялась.

## Разработка

```sh
.venv/bin/python -m pip install -r requirements-dev.lock
make check
```

Проверяются ruff, mypy, unit/SQLite integration и bot-to-gateway contracts.
Сетевые обращения тестов идут в stub; реальная сеть запрещена harness.
Coverage измеряет все файлы `relaypost/`, отдельно не менее 90% строк и ветвей.
Эти проверки подтверждают логику/контракты, но не живую доступность платформ.

[Архитектура](docs/architecture.md) · [Матрица проверок](docs/quality.md) ·
[Правила агента](AGENTS.md) · [Эксплуатация](docs/operations.md).
Скиллы и профильные правила установлены из локального Agent Skills Lab.
Рабочая ветка → PR в `develop` → PR из `develop` в `main`; без прямых push.
Релизный/deploy workflow пока не добавлен: CI ничего не публикует.

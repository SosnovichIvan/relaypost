# Architecture decision record

Используй формат ADR проекта. При его отсутствии достаточно следующих полей:

- Контекст: проблема, подтверждённые требования и ограничения.
- Статус: proposed/accepted/superseded, дата и связь с прежним решением.
- Варианты: полезные альтернативы и причины выбора; не добавляй заведомо
  непригодный вариант только ради таблицы.
- Решение: границы, ownership, контракт и конкретное изменение.
- Последствия: преимущества, оплачиваемая сложность, риски и обратимость.
- Проверка: observable criteria и условия пересмотра решения.

Предположение должно иметь способ проверки. «На будущее потребуется масштаб»
не обосновывает новую распределённую систему без сценария и последствий.
Для migration decision добавь порядок совместимых шагов и point of no return.
Не перезаписывай историю принятого ADR без принятой в проекте практики.

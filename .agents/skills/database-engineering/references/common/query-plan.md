# Диагностика запросов

Зафиксируй SQL и параметры, размер/распределение данных, время и число вызовов.
Отличай задержку запроса от pool wait, сети, N+1 и сериализации.

Начни с доступного плана без выполнения. Режим ANALYZE может исполнять запрос,
включая writes и функции с побочными эффектами; используй подходящую тестовую
среду и разрешение. Даже SELECT может быть дорогим или вызывать функцию.
ROLLBACK не является общей защитой от внешних эффектов и нагрузки.

Сравни estimates с actual rows/loops, если фактический план доступен. Проверь
фильтры, join fan-out, sort/spill, чтения и актуальность статистики. Seq scan
сам по себе не баг; индекс на маленькой таблице или неселективном предикате
может быть хуже. Не публикуй параметры с секретами или персональными данными.

После изменения сравни семантически одинаковые результаты и планы на
репрезентативных параметрах; учитывай cold/warm cache и цену writes. Без
измерений формулируй ожидаемый эффект как гипотезу.
